# SlothLog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build SlothLog, an offline, privacy-first developer companion that parses local Git commits across selected repositories, clusters work by Azure DevOps/Jira ticket IDs, estimates hours, and synthesizes executive-ready timesheet summaries using local open-weight AI (Google Gemma 2 2B via Ollama).

**Architecture:** A modular Python architecture featuring a native Git history inspector, ticket resolver, time-clustering algorithm, and Ollama Gemma 2 synthesizer with Sentry GenAI span tracing. Exposes both a standalone zero-dependency CLI and a FastAPI web server serving a high-density, single-click copy dashboard with SQLite caching.

**Tech Stack:** Python 3.10+, FastAPI, Uvicorn, SQLite3, Ollama (`gemma2:2b`), `sentry-sdk>=2.0.0`, Pydantic, Vanilla HTML/CSS/JS.

**Spec:** [docs/superpowers/specs/2026-10-20-slothlog-design.md](file:///D:/Git/Ale/slothlog/docs/superpowers/specs/2026-10-20-slothlog-design.md)

## Global Constraints

- All code, comments, docstrings, and commits must be in English.
- Every git commit MUST include `--author="Alessio Bianchini <alessio.bianchini@doit.it>"`.
- Runtime dependencies must remain lightweight: `fastapi`, `uvicorn`, `pydantic`, `sentry-sdk`. Zero heavy frameworks like LangChain or LlamaIndex.
- 100% offline first: Core functionality must work with no internet connection on `localhost`.
- Render deployment (`render.yaml`) must run smoothly on Render's free tier with auto-seeded demo timeslots.

## Review Focus

1. **Empty / Untagged Commits**: Repositories where developers made commits with no ticket IDs or messages like "wip" must cleanly group under a fallback category without crashing.
2. **Author Matching in Team Repos**: Commit author extraction must accurately match user's git config without pulling colleagues' commits into the timesheet.
3. **Time Cluster Spanning Midnight**: Commits spanning across midnight or with gaps > 12 hours must not produce absurd 18-hour single sessions.
4. **Ollama Offline Fallback**: If Ollama daemon is offline or cold, the system must degrade gracefully to raw commit aggregation rather than throwing 500 errors.
5. **Concurrent SQLite Access**: Both CLI and Web UI accessing `sloth.db` simultaneously must use SQLite WAL mode to prevent database locks.
